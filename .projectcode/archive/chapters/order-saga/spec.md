# order-saga 결제 실패 되돌리기

종류: 기능
배울 것: 사가, 보상, 규칙 두는 곳 정리
보여 줄 문제: 결제가 실패해도 재고가 줄어 있다

## 할 일
- S1 결제가 거절된 주문도 이벤트를 처리하면 재고가 줄어 있고 주문은 주문 접수로 남는 문제를 실행해 보여준다. Main은 노트북(120000원, 재고 10개) 1개를 김철수가 주문하고 결제해 거절되면, 이벤트를 처리한 뒤 노트북 재고와 주문 상태를 보여준다
- S2 상품은 재고를 수량만큼 되돌린다. 주문 취소하기는 주문을 취소로 저장한 뒤 주문 취소됨 이벤트를 이벤트 발행기에 넘긴다. 이벤트는 주문 번호와 주문 항목을 담는다. 취소할 수 없는 주문이면 이벤트를 넘기지 않는다
- S3 재고 되돌리기 처리기는 주문 취소됨 이벤트를 받아 주문 항목마다 상품 재고를 수량만큼 되돌리고 저장한다. 이벤트를 처리하기 전에는 재고가 그대로이고, 처리한 뒤에 되돌아온다
- S4 결제하기가 결제 창구에서 거절되면 보상으로 주문 취소하기를 하고 거절 이유로 거절한다. 주문은 취소가 되고, 이벤트를 처리하면 재고는 주문 전과 같다. 결제 완료 메시지는 없다. Main의 결제하기 장면이 주문 상태 취소와 되돌아온 노트북 재고를 보여준다
- S5 용어집에 주문 취소됨, 재고 되돌리기, 재고 되돌리기 처리기, 사가, 보상을 더하고, 재고 줄과 주문 취소하기 줄에 되돌리기를 넣는다
- S6 학생 문서 규칙 두는 곳에 값 객체, 애그리거트, 도메인 서비스, 명세, 이벤트, 사가, 응용 서비스마다 어떤 규칙을 두는지와 이 프로그램의 예를 표로 적고, 사가 절에 단계와 보상을 짝지어 적는다
- S7 컨텍스트 맵의 상품과 주문 줄에 재고 되돌리기 처리기가 주문 취소됨을 받는다는 것을, 주문과 회원 줄에 주문 조회 서비스도 회원 이름을 읽는다는 것을 더한다

## 실행 결과

===== 결제 실패 되돌리기 =====

[주문하기]
노트북 1개 주문: 1번 주문, 주문 접수
노트북 재고: 10개 -> 9개

[결제하기]
결제 거절: 결제 한도를 넘었습니다
주문 상태: 주문 접수 -> 주문 접수
노트북 재고: 9개 -> 9개

===== 결제 실패 되돌리기 =====

[주문하기]
노트북 1개 주문: 1번 주문, 주문 접수
노트북 재고: 10개 -> 9개

[결제하기]
결제 거절: 결제 한도를 넘었습니다
주문 상태: 주문 접수 -> 취소
노트북 재고: 9개 -> 10개

## 단계와 보상
| 단계 | 맡는 곳 | 실패하면 하는 보상 |
|---|---|---|
| 주문 접수 | 주문 응용 서비스 | 주문 취소 |
| 재고 줄이기 | 재고 줄이기 처리기 | 재고 되돌리기 |
| 결제 | 결제 창구 | 실패한 단계. 앞 단계를 보상한다 |

## 흐름
주문하기 -> 주문 접수됨 -> 재고 줄이기 -> 결제하기 -> 결제 거절 -> 보상으로 주문 취소하기 -> 주문 취소됨 -> 재고 되돌리기

## 그대로인 것
- 주문하기 장면은 고치기 전과 같다. 결제하기 장면의 주문 상태와 노트북 재고만 바뀐다
- 주문 응용 서비스를 만드는 모양은 그대로다
- 결제가 승인되는 결제하기는 그대로다

## 안 하는 것
- 사가를 맡는 조정 클래스: 안 만듦. 결제하기가 실패하면 취소하기를 부르고 나머지 단계는 이벤트로 잇는다
- 결제 거절 뒤 다시 결제하기: 안 만듦
- 재고가 모자란 주문 막기: 미룸
