# shipping-context 배송 컨텍스트

종류: 기능
배울 것: 공개 호스트 서비스, 발행된 언어

## 할 일
- S1 결제하기가 끝나면 주문 컨텍스트의 공개 호스트 서비스인 결제 완료 알리미가 결제 완료 메시지를 정해진 한 줄 글자 ORDER_PAID|orderId=주문 번호|address=배송 주소로 만들어 메시지 보내기에 넘긴다. Main은 보낸 메시지와 주문 상태를 전 -> 후로 보여준다
- S2 컨텍스트 맵에 공개 호스트 서비스와 발행된 언어 절을 더해 결제 완료 메시지의 모양을 적고, 용어집에 결제 완료 알리미, 메시지 보내기, 결제 완료 메시지를 더한다
- S3 배송 하위 도메인을 맡는 배송 컨텍스트 묶음 ddd.shipping의 domain에 배송과 배송 저장소, infrastructure에 메모리 배송 저장소를 둔다. 배송은 주문 번호와 배송 주소를 가진다
- S4 배송 컨텍스트의 결제 완료 메시지 처리기는 메시지 글자만 읽어 배송을 만들고 저장한다. 결제 완료가 아닌 메시지는 넘긴다. 배송 컨텍스트는 주문 컨텍스트의 클래스를 가져다 쓰지 않는다. Main은 1번 주문의 배송을 보여준다
- S5 컨텍스트 맵의 하위 도메인 표에 배송을, 컨텍스트 사이 표에 배송이 주문의 결제 완료 메시지를 읽는 줄을 더하고, 용어집에 배송, 배송 저장소, 결제 완료 메시지 처리기를 더한다

## 실행 결과
===== 배송 컨텍스트 =====

[결제 완료를 메시지로 알리기]
보낸 메시지: ORDER_PAID|orderId=1|address=서울시 강남구
주문 상태: 주문 접수 -> 결제 완료

[배송 컨텍스트가 메시지 읽어 배송 만들기]
배송 컨텍스트: 1번 주문, 서울시 강남구

## 메시지
ORDER_PAID|orderId=1|address=서울시 강남구
- 맨 앞은 메시지 종류다
- 그 뒤는 키=값이고 |로 나눈다

## 흐름
결제하기 -> 주문 저장 -> 결제 완료 알리미가 결제 완료 메시지 글자를 메시지 보내기에 넘김 -> 배송 컨텍스트가 글자를 읽음 -> 배송을 만들어 저장

## 그대로인 것
- 주문 응용 서비스는 메시지 보내기를 하나 더 받는다. 결제하기만 저장 뒤 결제 완료를 알린다
- 메시지 보내기는 Main이 람다로 만든다. 받은 글자를 찍고 배송 컨텍스트 처리기에 건넨다
- 주문 접수됨 이벤트와 재고 줄이기는 그대로다

## 안 하는 것
- 배송 컨텍스트가 배송 상태를 맡고 주문 상태와 맞추기: 미룸
- 같은 메시지를 두 번 받을 때 배송을 한 번만 만들기: 미룸
- 메시지 값에 들어간 |와 = 처리하기: 안 만듦. 메시지 형식은 한 줄 글자로 둔다
