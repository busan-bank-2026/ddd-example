# order-query 주문 목록 조회

종류: 기능
배울 것: CQRS

## 할 일
- S1 주문 저장소는 회원 번호로 그 회원의 주문을 모두 꺼낸다. 다른 회원의 주문은 꺼내지 않고, 주문이 없는 회원은 빈 목록이다
- S2 주문 요약은 주문 목록 화면 한 줄에 맞춘 읽기 모델이다. 주문 번호, 회원 이름, 항목 수, 결제 금액, 상태 글자를 숫자와 글자로만 가진다. 바꾸는 동작이 없다
- S3 주문 조회 서비스는 회원 번호로 그 회원의 주문 요약 목록을 돌려준다. 주문을 바꾸거나 저장하지 않는다. 주문 응용 서비스와 따로 있고 결제 창구와 발행기를 모른다. Main은 김철수의 주문 목록을 보여준다
- S4 용어집에 주문 요약, 주문 조회 서비스, 명령과 조회 나누기를 더한다

## 실행 결과
===== 주문 목록 조회 =====

[주문하기]
보낸 메시지: ORDER_PAID|orderId=1|address=서울시 강남구
김철수 주문: 1번, 2번
이영희 주문: 3번

[김철수의 주문 목록]
1번 주문: 김철수, 항목 2개, 31000원, 결제 완료
2번 주문: 김철수, 항목 1개, 3000원, 주문 접수

## 명령과 조회
| | 명령 쪽 | 조회 쪽 |
|---|---|---|
| 하는 일 | 주문하기, 결제하기, 배송하기, 취소하기 | 주문 목록 보기 |
| 맡는 곳 | 주문 응용 서비스 | 주문 조회 서비스 |
| 모델 | 주문 애그리거트. 규칙을 지키며 상태를 바꾼다 | 주문 요약. 화면 한 줄에 맞춘 숫자와 글자 |
| 저장 | 한다 | 하지 않는다 |

## 흐름
회원 번호 -> 주문 조회 서비스 -> 주문 저장소에서 그 회원의 주문 꺼냄 -> 회원 이름을 더해 주문 요약으로 옮김 -> 주문 요약 목록

## 그대로인 것
- 주문 응용 서비스의 명령은 그대로다

## 안 하는 것
- 읽기 모델을 따로 저장하고 이벤트로 채우기: 안 만듦. 조회 서비스가 주문 저장소에서 바로 읽는다
- 주문 목록 쪽 나누기와 정렬: 안 만듦
