# payment-acl 외부 결제 연결

종류: 기능
배울 것: 부패 방지 계층, 컨텍스트 맵

## 할 일
- S1 외부 결제 모듈은 우리 말과 다른 모양으로 말한다. 가게 키와 원 단위 정수 금액을 받아 승인이면 0000, 10만 원을 넘으면 E101, 가게 키가 틀리면 E201 코드 글자를 돌려준다. 외부 모듈은 ddd 밖 묶음에 둔다. Main은 27900원과 108000원을 직접 맡겨 받은 코드 글자를 보여준다
- S2 주문 컨텍스트는 결제를 우리 말로 정한다. 결제 창구는 결제 금액을 받아 결제 결과를 돌려준다. 결제 결과는 승인인지와 거절 이유를 가진다. 주문 도메인과 응용 계층은 외부 결제 모듈을 모른다
- S3 결제 어댑터는 결제 창구를 구현한다. 결제 금액에 가게 키를 붙여 외부 모듈에 맡기고, 받은 코드 글자를 결제 결과로 번역한다. 0000은 승인, E101은 거절 이유 결제 한도를 넘었습니다, 다른 코드는 거절 이유 결제에 실패했습니다다
- S4 결제하기는 결제 금액을 결제 창구에 맡긴다. 승인이면 저장하고 결제 완료 메시지를 넘긴다. 거절이면 거절 이유로 결제를 거절하고, 주문은 주문 접수로 남고, 결제 완료 메시지도 없다. Main은 자바 책 2개 주문의 승인과 자바 책 8개 주문의 거절 이유와 주문 상태를 보여준다
- S5 용어집에 결제 창구, 결제 결과, 결제 어댑터를 더한다. 외부 모듈의 코드 글자와 가게 키는 용어집에 올리지 않는다
- S6 컨텍스트 맵에 부패 방지 계층 절을 더해 외부 결제 모듈의 말과 우리 말을 표로 잇고, 하위 도메인 표에 결제를, 컨텍스트 사이 표에 주문이 외부 결제를 결제 어댑터로 쓰는 줄을 더한다. 용어집에 부패 방지 계층을 더한다

## 실행 결과
===== 외부 결제 연결 =====

[외부 결제 모듈에 직접 맡기기]
27900원 맡기기: 0000
108000원 맡기기: E101

[결제 어댑터로 결제하기]
보낸 메시지: ORDER_PAID|orderId=1|address=서울시 강남구
주문 상태: 주문 접수 -> 결제 완료

[한도 넘은 결제]
자바 책 8개 결제: 결제 한도를 넘었습니다
주문 상태: 주문 접수 -> 주문 접수

## 외부 말과 우리 말
| 외부 결제 모듈 | 주문 컨텍스트 |
|---|---|
| 가게 키 | 결제 어댑터만 안다 |
| amountWon | 결제 금액 |
| 0000 | 승인 |
| E101 | 거절. 결제 한도를 넘었습니다 |
| 그 밖의 코드 | 거절. 결제에 실패했습니다 |

## 흐름
결제하기 -> 결제 창구에 결제 금액 맡김 -> 결제 어댑터가 외부 모듈에 결제 금액과 가게 키로 승인 요청 -> 코드 글자를 결제 결과로 번역 -> 승인이면 저장하고 결제 완료 메시지, 거절이면 거절 이유로 거절

## 그대로인 것
- 결제 완료 알리미와 배송 컨텍스트는 그대로다
- 주문하기와 할인 정책은 그대로다

## 안 하는 것
- 결제가 거절되면 줄인 재고 되돌리기와 주문 취소: order-saga 장
- 외부 결제의 시간 초과와 다시 시도: 안 만듦
- 외부 결제로 환불하기: 안 만듦. 반품과 환불은 하지 않는다
