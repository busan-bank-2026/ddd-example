# 로드맵

강의: 온라인 주문으로 배우는 도메인 주도 설계(DDD)
목표: DDD를 이해하고, 문제를 발견하고, 코드로 고치며 해결한다
대상: DDD를 처음 배우는 사람
결과물: 주문, 결제, 배송, 취소가 되는 순수 자바 주문 프로그램

## 선수 지식

- 자바: 클래스, 인터페이스, enum, record, 예외
- 자바: 컬렉션(List, Map), 람다, 패키지

## 학습 목표

- 전술 설계: 엔티티, 값 객체, 애그리거트, 리포지터리, 팩토리, 서비스, 이벤트, 명세
- 전략 설계: 유비쿼터스 언어, 하위 도메인, 바운디드 컨텍스트, 컨텍스트 맵, 부패 방지 계층
- 구조와 일관성: 계층 구조, 의존성 역전, 트랜잭션 경계, 최종 일관성, CQRS, 사가
- 규칙을 어디에 둘지 고르기: 값 객체, 애그리거트, 도메인 서비스, 이벤트, 사가, 응용 서비스

## 진행 방식

- 따라치기: DDD 코드다. 학생이 직접 친다
- 붙여넣기: DDD가 아닌 기반 코드다. 완성본을 복사한다
- 문제가 적힌 장은 문제를 먼저 실행해 보고 고친다

## 미룬 것

- 화면과 HTTP API
- 주문 항목 빼기와 수량 바꾸기
- 없는 회원 번호로 주문 막기
- 배송비를 더한 총 결제 금액
- 재고가 모자란 주문 막기
- 배송 컨텍스트가 배송 상태를 맡고 주문 상태와 맞추기
- 같은 메시지를 두 번 받을 때 배송을 한 번만 만들기

## 하지 않는 것

- 헥사고날 아키텍처
- Spring, JPA 같은 프레임워크
- 실제 메시지 큐 제품(Kafka, RabbitMQ)과 분산 시스템
- JSON
- 이벤트 소싱
- 쿠폰, 장바구니, 알림
- 콘솔 입력 메뉴. Main은 코드에 적은 장면을 실행해 출력한다
- 반품과 환불
- 회원 등급으로 무료 배송 정하기
- 오라클 같은 실제 DB 저장소. 저장소를 바꿔 끼우는 것은 order-repository와 layers 장에서 보인다
- 낙관적 잠금에 거절된 쪽 다시 하기. 주문 응용 서비스는 일마다 주문을 새로 꺼낸다
- 상품과 회원의 버전. 낙관적 잠금은 주문 하나로 보인다
- 비관적 잠금
- 컨텍스트마다 돈을 따로 두기. 돈은 공유 커널로 함께 쓴다
- 자바 모듈로 다른 컨텍스트의 클래스를 못 쓰게 막기
- 용어집을 컨텍스트마다 나누기
- 회원 응용 서비스
- 메시지 값에 들어간 |와 = 처리하기
- 외부 결제의 시간 초과와 다시 시도
- 읽기 모델을 따로 저장하고 이벤트로 채우기. 조회 서비스가 주문 저장소에서 바로 읽는다
- 주문 목록 쪽 나누기와 정렬
- 사가를 맡는 조정 클래스. 결제하기가 실패하면 취소하기를 부르고 나머지는 이벤트로 잇는다
- 결제 거절 뒤 다시 결제하기
