## 미룬 것

- 화면과 HTTP API: 장 정하지 않음
- 주문 항목 빼기와 수량 바꾸기: 장 정하지 않음
- 없는 회원 번호로 주문 막기: 장 정하지 않음
- 배송비를 더한 총 결제 금액: 장 정하지 않음
- 재고가 모자란 주문 막기: 장 정하지 않음
- 배송 컨텍스트가 배송 상태를 맡고 주문 상태와 맞추기: 장 정하지 않음
- 같은 메시지를 두 번 받을 때 배송을 한 번만 만들기: 장 정하지 않음

## 하지 않는 것

- 헥사고날 아키텍처
- Spring, JPA 같은 프레임워크
- 실제 메시지 큐 제품(Kafka, RabbitMQ)과 분산 시스템
- JSON
- 이벤트 소싱
- 쿠폰, 장바구니, 알림
- 콘솔 입력 메뉴. Main은 코드에 적은 장면을 실행해 출력한다
- 반품과 환불
- 회원 등급으로 무료 배송 정하기
- 오라클 같은 실제 DB 저장소. 저장소를 바꿔 끼우는 것은 order-repository와 layers 장에서 보인다
- 낙관적 잠금에 거절된 쪽 다시 하기. 주문 응용 서비스는 일마다 주문을 새로 꺼낸다
- 상품과 회원의 버전. 낙관적 잠금은 주문 하나로 보인다
- 비관적 잠금
- 돈 값 객체와 공유 커널. 금액은 int로 두고 주문이 계산한다
- 자바 모듈로 다른 컨텍스트의 클래스를 못 쓰게 막기
- 용어집을 컨텍스트마다 나누기
- 회원 응용 서비스
- 메시지 값에 들어간 |와 = 처리하기
- 외부 결제의 시간 초과와 다시 시도
- 읽기 모델을 따로 저장하고 이벤트로 채우기. 조회 서비스가 주문 저장소에서 바로 읽는다
- 주문 목록 쪽 나누기와 정렬
- 사가를 맡는 조정 클래스. 결제하기가 실패하면 취소하기를 부르고 나머지는 이벤트로 잇는다
- 결제 거절 뒤 다시 결제하기
- 배송 앱이 소켓 메시지를 여러 개 계속 받기. 메시지 하나를 받고 끝난다
- 받는 쪽이 꺼져 있을 때 메시지를 모아 두었다가 다시 보내기
