# place-order 주문하기 유스케이스

종류: 기능
배울 것: 응용 서비스

## 할 일
- S1 주문하기는 주문 요청 하나를 받는다. 주문 요청은 주문자, 주문 항목 요청 목록, 배송 주소를 담고, 주문 항목 요청은 상품 이름, 가격, 수량을 담는다. 요청은 밖에서 들어오는 값 묶음(DTO)이다
- S2 주문하기는 주문 요청으로 주문을 만들어 주문 저장소에 저장하고 주문 번호를 돌려준다
- S3 주문 항목 더하기는 주문 번호와 주문 항목 요청을 받아 주문을 꺼내 주문에게 시키고 다시 저장한다
- S4 요청의 값이 규칙에 맞지 않으면 주문, 주문 항목, 주소가 정한 거절 말 그대로 거절하고 아무것도 저장하지 않는다
- S5 주문 응용 서비스가 결제하기, 배송하기, 배송 완료하기, 주문 취소하기를 주문 번호로 받아 주문을 꺼내 주문에게 시키고 다시 저장한다
- S6 용어집에 주문 응용 서비스, 주문 요청, 주문 항목 요청을 더한다

## 실행 결과
온라인 주문 프로그램을 시작합니다
주문: 1번, 김철수, 31000원, 주문 접수
주문 항목: 자바 책 2개, 30000원
주문 항목: 볼펜 1개, 1000원
결제: 결제 완료
배송: 배송 중
취소: 배송 중인 주문은 취소할 수 없습니다
결제 없이 배송: 주문 접수인 주문은 배송할 수 없습니다
음수 금액 주문: 금액은 0원 이상이어야 합니다
빈 주소 주문: 배송 주소를 입력해야 합니다
항목 더하기: 항목 3개, 주문 금액 41000원
결제 뒤 항목 더하기: 주문 접수인 주문에만 항목을 더할 수 있습니다
빈 주문: 주문 항목이 하나 이상 있어야 합니다
0개 항목 주문: 수량은 1개 이상이어야 합니다
두 번 결제: 결제 완료인 주문은 결제할 수 없습니다
배송 완료: 배송 완료
없는 주문 결제: 주문이 없습니다
저장 안 한 취소: 주문 접수

## 흐름
주문 요청 -> 주문 응용 서비스가 주문 항목과 주소로 바꾸기 -> 주문 만들기 -> 저장하기 -> 주문 번호 돌려주기

## 그대로인 것
- 실행 출력 열여덟 줄은 바뀌지 않는다. Main이 부르는 모양만 요청으로 바뀐다
- 규칙은 주문, 주문 항목, 주소, 주문 상태에 그대로 있다. 응용 서비스는 규칙을 갖지 않는다

## 안 하는 것
- 결제하기 같은 다른 유스케이스의 요청: 안 만듦. 주문 번호 하나라 묶을 것이 없다
- 요청 값 미리 검사하기: 안 만듦. 검사는 도메인이 한다
- 패키지 나누기: layers 장
- 할인 같은 여러 애그리거트에 걸친 규칙: discount 장
