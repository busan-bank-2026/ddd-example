# id-reference 회원과 상품

종류: 기능
배울 것: 애그리거트 간 ID 참조

## 할 일
- S1 회원은 회원 번호와 이름을, 상품은 상품 번호, 이름, 가격을 가진다. 번호가 같으면 같은 회원, 같은 상품이다
- S2 회원 저장소와 상품 저장소에 회원과 상품을 저장하고 번호로 꺼낸다. 저장소 약속은 도메인 계층에, 메모리 구현은 인프라 계층에 두고, Main이 주문 전에 회원과 상품을 먼저 저장한다
- S3 주문은 회원을 객체로 갖지 않고 회원 번호로 가리킨다. 주문 요청은 주문자 이름 대신 회원 번호를 담고, Main은 주문의 회원 번호로 회원 저장소에서 회원을 찾아 이름을 보여준다
- S4 주문 항목은 상품을 객체로 갖지 않고 상품 번호로 가리킨다. 주문 항목 요청과 주문 항목은 상품 번호, 주문 때의 상품 이름, 가격, 수량을 담는다
- S5 주문 뒤 상품 가격이 바뀌어도 주문 항목의 가격과 주문 금액은 주문 때 그대로다
- S6 용어집에 회원, 회원 저장소, 상품, 상품 저장소, 회원 번호, 상품 번호를 더하고 주문자 줄을 회원 번호로 바꾼다

## 실행 결과
===== 회원과 상품 =====

[회원과 상품 저장하기]
1번 회원: 김철수
1번 상품: 자바 책 15000원

[회원 번호와 상품 번호로 주문하기]
주문: 1번 주문, 1번 회원 김철수, 31000원
주문 항목: 1번 상품 자바 책 2개, 30000원
주문 항목: 2번 상품 볼펜 1개, 1000원

[상품 가격이 바뀐 뒤 주문 보기]
자바 책 상품 가격: 15000원 -> 18000원
자바 책 주문 항목 가격: 15000원 -> 15000원
주문 금액: 31000원 -> 31000원

## 흐름
회원과 상품 저장 -> 회원 번호와 상품 번호로 주문하기 -> 주문의 회원 번호로 회원 찾기 -> 상품 가격 바꾸기 -> 주문 항목은 주문 때 가격 그대로

## 그대로인 것
- 주문, 주문 항목, 주소, 주문 상태의 규칙은 그대로다
- 주문 응용 서비스는 지금처럼 주문 저장소만 받는다

## 안 하는 것
- 상품 저장소에서 상품을 찾아 주문 항목 만들기: order-factory 장
- 회원 등급: discount 장
- 상품 재고: order-events 장
- 없는 회원 번호로 주문 막기: 미룸
- 회원과 상품을 고치는 동작: 안 만듦. 가격이 바뀐 상품은 같은 번호로 다시 저장한다
