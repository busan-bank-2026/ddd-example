# rich-entity 규칙을 가진 주문

종류: 리팩터
배울 것: 엔티티, 식별자, 행동 메서드
보여 줄 문제: 결제 안 한 주문이 배송된다

## 할 일
- S1 결제하지 않은 주문의 상태를 서비스를 거치지 않고 배송 중으로 바꾸면 그대로 바뀌는 문제를 실행해 보여준다
- S2 주문은 만들 때 주문 번호를 받고, 같은 번호면 같은 주문으로 본다
- S3 주문을 만들 때 주문 금액과 주문 접수 상태를 주문이 스스로 정한다
- S4 결제, 배송, 취소 규칙을 주문이 스스로 지킨다. 서비스는 주문에게 시키기만 한다
- S5 주문 밖에서는 상태를 직접 바꿀 수 없다. 결제 안 한 주문을 배송하라고 하면 주문이 거절한다
- S6 용어집에 주문 번호를 더한다

## 실행 결과
문제를 보여줄 때 (S1)
결제 없이 배송: 배송 중

고친 뒤
온라인 주문 프로그램을 시작합니다
주문: 1번, 김철수, 자바 책 2개, 30000원, 주문 접수
결제: 결제 완료
배송: 배송 중
취소: 배송 중인 주문은 취소할 수 없습니다
결제 없이 배송: 결제하지 않은 주문은 배송할 수 없습니다

## 흐름
문제 장면 실행 -> 규칙을 주문으로 옮기기 -> 상태 바꾸는 길 막기 -> 같은 장면이 거절됨

## 그대로인 것
- 결제, 배송, 취소 규칙과 예외 메시지는 바뀌지 않는다
- 용어집의 업무 말과 코드 이름은 그대로다
- 상태는 글자 그대로 둔다. 상태 전이는 order-status 장이다
- 금액과 주소 검사는 하지 않는다. value-object 장이다
