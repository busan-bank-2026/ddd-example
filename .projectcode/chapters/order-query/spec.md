# order-query 주문 목록 조회

종류: 기능
배울 것: CQRS

## 할 일
- S1 주문 저장소는 회원 번호로 그 회원의 주문을 모두 꺼낸다. 다른 회원의 주문은 꺼내지 않고, 주문이 없는 회원은 빈 목록이다
- S2 주문 요약은 주문 목록 화면 한 줄에 맞춘 읽기 모델이다. 주문 번호, 회원 이름, 항목 수, 결제 금액, 상태 글자를 숫자와 글자로만 가진다. 바꾸는 동작이 없다
- S3 주문 조회 서비스는 회원 번호로 그 회원의 주문 요약 목록을 돌려준다. 주문을 바꾸거나 저장하지 않는다. 주문 응용 서비스와 따로 있고 결제 창구와 발행기를 모른다. Main은 김철수의 주문 목록을 보여준다
- S4 용어집에 주문 요약, 주문 조회 서비스, 명령과 조회 나누기를 더한다

## 실행 결과
온라인 주문 프로그램을 시작합니다
주문: 1번, 김철수, 31000원, 주문 접수
주문 항목: 자바 책 2개, 30000원
주문 항목: 볼펜 1개, 1000원
주문 뒤: 이벤트 1개, 자바 책 재고 10개
이벤트 처리 뒤: 자바 책 재고 8개
결제: 결제 완료
할인: VIP 3100원, 결제 금액 27900원
배송비: 3000원
배송: 배송 중
취소: 배송 중인 주문은 취소할 수 없습니다
결제 없이 배송: 주문 접수인 주문은 배송할 수 없습니다
음수 금액 주문: 금액은 0원 이상이어야 합니다
빈 주소 주문: 배송 주소를 입력해야 합니다
항목 더하기: 항목 3개, 주문 금액 41000원
결제 뒤 항목 더하기: 주문 접수인 주문에만 항목을 더할 수 있습니다
빈 주문: 주문 항목이 하나 이상 있어야 합니다
0개 항목 주문: 수량은 1개 이상이어야 합니다
두 번 결제: 결제 완료인 주문은 결제할 수 없습니다
배송 완료: 배송 완료
없는 주문 결제: 주문이 없습니다
없는 상품 주문: 상품이 없습니다
저장 안 한 취소: 주문 접수
6만원 주문 배송비: 서울 0원, 제주 3000원
가격 바뀐 뒤: 1번 상품 18000원, 주문 항목 15000원, 주문 금액 31000원
동시 수정: 다른 곳에서 먼저 바꾼 주문입니다
결제 완료 메시지: ORDER_PAID|orderId=1|address=서울시 강남구
결제 완료 메시지: ORDER_PAID|orderId=4|address=광주시 북구
배송 컨텍스트: 1번 주문, 서울시 강남구
외부 결제 응답: 27900원 0000, 108000원 E101
한도 넘은 결제: 결제 한도를 넘었습니다, 주문 접수
주문 목록: 1번, 김철수, 항목 2개, 27900원, 배송 완료

## 명령과 조회
| | 명령 쪽 | 조회 쪽 |
|---|---|---|
| 하는 일 | 주문하기, 결제하기, 배송하기, 취소하기 | 주문 목록 보기 |
| 맡는 곳 | 주문 응용 서비스 | 주문 조회 서비스 |
| 모델 | 주문 애그리거트. 규칙을 지키며 상태를 바꾼다 | 주문 요약. 화면 한 줄에 맞춘 숫자와 글자 |
| 저장 | 한다 | 하지 않는다 |

## 흐름
회원 번호 -> 주문 조회 서비스 -> 주문 저장소에서 그 회원의 주문 꺼냄 -> 회원 이름을 더해 주문 요약으로 옮김 -> 주문 요약 목록

## 그대로인 것
- 앞 장 출력 서른한 줄은 바뀌지 않는다. 마지막 줄 다음에 한 줄을 더한다
- 주문 응용 서비스의 명령은 그대로다

## 안 하는 것
- 읽기 모델을 따로 저장하고 이벤트로 채우기: 안 만듦. 조회 서비스가 주문 저장소에서 바로 읽는다
- 주문 목록 쪽 나누기와 정렬: 안 만듦
