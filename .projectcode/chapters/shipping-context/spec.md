# shipping-context 배송 컨텍스트

종류: 기능
배울 것: 공개 호스트 서비스, 발행된 언어

## 할 일
- S1 결제하기가 끝나면 주문 컨텍스트의 공개 호스트 서비스가 결제 완료 메시지를 정해진 한 줄 글자 ORDER_PAID|orderId=주문 번호|address=배송 주소로 만들어 이벤트 발행기에 넘긴다. Main은 이벤트를 처리할 때 받은 메시지를 보여준다
- S2 컨텍스트 맵에 공개 호스트 서비스와 발행된 언어 절을 더해 결제 완료 메시지의 모양을 적고, 용어집에 공개 호스트 서비스와 결제 완료 메시지를 더한다
- S3 배송 하위 도메인을 맡는 배송 컨텍스트 묶음 ddd.shipping의 domain에 배송과 배송 저장소, infrastructure에 메모리 배송 저장소를 둔다. 배송은 주문 번호와 배송 주소를 가진다
- S4 배송 컨텍스트의 결제 완료 메시지 처리기는 메시지 글자만 읽어 배송을 만들고 저장한다. 결제 완료가 아닌 메시지는 넘긴다. 배송 컨텍스트는 주문 컨텍스트의 클래스를 가져다 쓰지 않는다. Main은 1번 주문의 배송을 보여준다
- S5 컨텍스트 맵의 하위 도메인 표에 배송을, 컨텍스트 사이 표에 배송이 주문의 결제 완료 메시지를 읽는 줄을 더하고, 용어집에 배송, 배송 저장소, 결제 완료 메시지 처리기를 더한다

## 실행 결과
온라인 주문 프로그램을 시작합니다
주문: 1번, 김철수, 31000원, 주문 접수
주문 항목: 자바 책 2개, 30000원
주문 항목: 볼펜 1개, 1000원
주문 뒤: 이벤트 1개, 자바 책 재고 10개
이벤트 처리 뒤: 자바 책 재고 8개
결제: 결제 완료
할인: VIP 3100원, 결제 금액 27900원
배송비: 3000원
배송: 배송 중
취소: 배송 중인 주문은 취소할 수 없습니다
결제 없이 배송: 주문 접수인 주문은 배송할 수 없습니다
음수 금액 주문: 금액은 0원 이상이어야 합니다
빈 주소 주문: 배송 주소를 입력해야 합니다
항목 더하기: 항목 3개, 주문 금액 41000원
결제 뒤 항목 더하기: 주문 접수인 주문에만 항목을 더할 수 있습니다
빈 주문: 주문 항목이 하나 이상 있어야 합니다
0개 항목 주문: 수량은 1개 이상이어야 합니다
두 번 결제: 결제 완료인 주문은 결제할 수 없습니다
배송 완료: 배송 완료
없는 주문 결제: 주문이 없습니다
없는 상품 주문: 상품이 없습니다
저장 안 한 취소: 주문 접수
6만원 주문 배송비: 서울 0원, 제주 3000원
가격 바뀐 뒤: 1번 상품 18000원, 주문 항목 15000원, 주문 금액 31000원
동시 수정: 다른 곳에서 먼저 바꾼 주문입니다
결제 완료 메시지: ORDER_PAID|orderId=1|address=서울시 강남구
결제 완료 메시지: ORDER_PAID|orderId=4|address=광주시 북구
배송 컨텍스트: 1번 주문, 서울시 강남구

## 메시지
ORDER_PAID|orderId=1|address=서울시 강남구
- 맨 앞은 메시지 종류다
- 그 뒤는 키=값이고 |로 나눈다

## 흐름
결제하기 -> 주문 저장 -> 공개 호스트 서비스가 결제 완료 메시지 글자를 발행기에 넘김 -> 이벤트 처리 -> 배송 컨텍스트가 글자를 읽음 -> 배송을 만들어 저장

## 그대로인 것
- 앞 장 출력 스물여섯 줄은 바뀌지 않는다. 마지막 줄 다음에 세 줄을 더한다
- 주문 응용 서비스를 만드는 법은 그대로다. 결제하기만 저장 뒤 메시지를 넘긴다
- 주문 접수됨 이벤트와 재고 줄이기는 그대로다

## 안 하는 것
- 배송 컨텍스트가 배송 상태를 맡고 주문 상태와 맞추기: 미룸
- 같은 메시지를 두 번 받을 때 배송을 한 번만 만들기: 미룸
- 메시지 값에 들어간 |와 = 처리하기: 안 만듦. 메시지 형식은 한 줄 글자로 둔다
