# optimistic-lock 동시 수정 막기

종류: 기능
배울 것: 낙관적 잠금
보여 줄 문제: 나중 저장이 덮어써 배송 중 주문이 취소된다

## 할 일
- S1 결제 완료인 같은 주문을 두 번 꺼내 첫째로 배송하고 저장한 뒤, 옛 상태인 둘째로 취소하고 저장하면 배송 중인 주문이 취소로 덮이는 문제를 실행해 보여준다
- S2 주문은 버전을 가진다. 새 주문은 버전 0이고, 주문 저장소에 저장할 때마다 버전이 1씩 오른다. 꺼낸 주문은 저장된 버전을 가진다. Main이 결제하고 저장한 주문의 버전을 전 -> 후로 보여준다
- S3 주문 저장소는 저장된 주문과 저장하려는 주문의 버전이 다르면 다른 곳에서 먼저 바꾼 주문이라고 저장을 거절한다. 거절되면 저장된 주문은 그대로다. Main의 동시 수정 장면은 거절 메시지와 저장된 주문 상태를 보여준다
- S4 용어집에 버전을 더하고 저장하기 줄에 버전 확인을 넣는다

## 실행 결과
문제를 보여줄 때 (S1)
===== 동시 수정 막기 =====

[같은 주문을 두 번 꺼내 저장하기]
첫째로 꺼내 배송: 결제 완료 -> 배송 중
둘째로 꺼내 취소: 배송 중 -> 취소

고친 뒤
===== 동시 수정 막기 =====

[같은 주문을 두 번 꺼내 저장하기]
첫째로 꺼내 배송: 결제 완료 -> 배송 중
둘째로 꺼내 취소: 다른 곳에서 먼저 바꾼 주문입니다
저장된 주문 상태: 배송 중

[저장할 때마다 버전 올리기]
결제하고 저장: 버전 1 -> 2

## 흐름
같은 주문을 두 번 꺼냄 -> 첫째로 배송하고 저장 -> 옛 주문인 둘째로 취소하고 저장 -> 배송 중이 취소로 덮임 -> 주문에 버전 -> 저장할 때 버전 비교 -> 버전이 다르면 거절

## 그대로인 것
- T2까지는 버전만 오르고 비교하지 않아서 둘째로 꺼내 취소 줄은 배송 중 -> 취소 그대로다
- 주문 응용 서비스는 그대로다. 일마다 주문을 새로 꺼내 시키고 저장하므로 버전이 맞는다

## 안 하는 것
- 거절된 쪽이 다시 꺼내 다시 하기: 안 만듦. 주문 응용 서비스는 이미 일마다 새로 꺼낸다
- 상품과 회원의 버전: 안 만듦. 이 장은 주문 하나로 낙관적 잠금을 보인다
- 비관적 잠금(꺼낼 때 잠가 두기): 안 만듦
