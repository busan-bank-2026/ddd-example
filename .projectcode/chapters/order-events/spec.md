# order-events 주문 뒤 재고 줄이기

종류: 기능
배울 것: 도메인 이벤트, 트랜잭션 경계, 최종 일관성

## 할 일
- S1 상품은 재고를 가진다. 상품을 만들 때 재고를 정하고 물으면 답한다. Main은 자바 책을 재고 10개로 저장한다
- S2 주문은 만들어질 때 주문 접수됨 이벤트를 남긴다. 이벤트는 주문 번호와 주문 항목을 담는다. 주문은 상품 재고를 직접 줄이지 않는다. Main이 자바 책 2개 주문 뒤 남긴 이벤트 수와 자바 책 재고를 전 -> 후로 보여준다
- S3 주문 응용 서비스는 주문을 저장한 뒤 주문이 남긴 이벤트를 이벤트 발행기에 넘긴다. 이벤트 발행기는 받은 이벤트를 쌓아 두었다가, 이벤트를 처리할 때 구독한 이벤트 처리기마다 한 번씩 보낸다. 이벤트 처리기는 받은 이벤트 중 자기 것만 골라 처리한다
- S4 재고 줄이기 처리기는 주문 접수됨 이벤트를 받아 주문 항목마다 상품 재고를 수량만큼 줄이고 저장한다. 이벤트를 처리하기 전에는 주문만 저장되고 재고는 그대로이고, 처리한 뒤에 재고가 맞춰진다. Main이 이벤트 처리 전 -> 후 자바 책 재고를 보여준다
- S5 용어집에 재고, 주문 접수됨, 이벤트 발행기, 이벤트 처리기, 재고 줄이기, 재고 줄이기 처리기를 더하고 상품 줄에 재고를 넣는다

## 실행 결과
===== 주문 뒤 재고 줄이기 =====

[주문이 주문 접수됨 이벤트 남기기]
자바 책 2개 주문: 1번 주문, 이벤트 1개
자바 책 재고: 10개 -> 10개

[이벤트를 처리해 재고 줄이기]
자바 책 재고: 10개 -> 8개

## 흐름
주문하기 -> 주문이 주문 접수됨 이벤트를 남김 -> 주문 저장 -> 발행기에 이벤트 쌓기 -> 나중에 이벤트 처리 -> 재고 줄이기 처리기가 재고를 줄이고 저장

## 그대로인 것
- T2까지는 이벤트가 발행기에 쌓이기만 해서 주문 뒤 재고는 그대로 10개다
- 주문 응용 서비스를 만드는 모양은 발행기만큼 바뀐다. 결제, 배송, 취소는 그대로다
- 주문 금액, 할인, 배송비 규칙은 그대로다

## 안 하는 것
- 재고가 모자란 주문 막기: 미룸. 주문과 재고가 따로 맞춰지므로 모자란 것을 나중에 알게 되고, 되돌리는 일은 사가에서 배운다
- 주문 취소 때 재고 되돌리기: 미룸
- 결제 완료 같은 다른 이벤트: 이 장은 주문 접수됨 하나만 만든다
