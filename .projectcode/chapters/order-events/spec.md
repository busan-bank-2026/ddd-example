# order-events 주문 뒤 재고 줄이기

종류: 기능
배울 것: 도메인 이벤트, 트랜잭션 경계, 최종 일관성

## 할 일
- S1 상품은 재고를 가진다. 상품을 만들 때 재고를 정하고 물으면 답한다. Main은 상품마다 재고 10개로 저장한다
- S2 주문은 만들어질 때 주문 접수됨 이벤트를 남긴다. 이벤트는 주문 번호와 주문 항목을 담는다. 주문은 상품 재고를 직접 줄이지 않는다. Main이 첫 주문 항목 다음에 남긴 이벤트 수와 자바 책 재고를 보여준다
- S3 주문 응용 서비스는 주문을 저장한 뒤 주문이 남긴 이벤트를 이벤트 발행기에 넘긴다. 이벤트 발행기는 받은 이벤트를 쌓아 두었다가, 이벤트를 처리할 때 그 이벤트를 구독한 곳에 한 번씩 보낸다
- S4 재고 줄이기 처리기는 주문 접수됨 이벤트를 받아 주문 항목마다 상품 재고를 수량만큼 줄이고 저장한다. 이벤트를 처리하기 전에는 주문만 저장되고 재고는 그대로이고, 처리한 뒤에 재고가 맞춰진다. Main이 이벤트 처리 뒤 자바 책 재고를 보여준다
- S5 용어집에 재고, 주문 접수됨, 이벤트 발행기, 재고 줄이기, 재고 줄이기 처리기를 더하고 상품 줄에 재고를 넣는다

## 실행 결과
온라인 주문 프로그램을 시작합니다
주문: 1번, 김철수, 31000원, 주문 접수
주문 항목: 자바 책 2개, 30000원
주문 항목: 볼펜 1개, 1000원
주문 뒤: 이벤트 1개, 자바 책 재고 10개
이벤트 처리 뒤: 자바 책 재고 8개
결제: 결제 완료
할인: VIP 3100원, 결제 금액 27900원
배송비: 3000원
배송: 배송 중
취소: 배송 중인 주문은 취소할 수 없습니다
결제 없이 배송: 주문 접수인 주문은 배송할 수 없습니다
음수 금액 주문: 금액은 0원 이상이어야 합니다
빈 주소 주문: 배송 주소를 입력해야 합니다
항목 더하기: 항목 3개, 주문 금액 41000원
결제 뒤 항목 더하기: 주문 접수인 주문에만 항목을 더할 수 있습니다
빈 주문: 주문 항목이 하나 이상 있어야 합니다
0개 항목 주문: 수량은 1개 이상이어야 합니다
두 번 결제: 결제 완료인 주문은 결제할 수 없습니다
배송 완료: 배송 완료
없는 주문 결제: 주문이 없습니다
없는 상품 주문: 상품이 없습니다
저장 안 한 취소: 주문 접수
6만원 주문 배송비: 서울 0원, 제주 3000원
가격 바뀐 뒤: 1번 상품 18000원, 주문 항목 15000원, 주문 금액 31000원

## 흐름
주문하기 -> 주문이 주문 접수됨 이벤트를 남김 -> 주문 저장 -> 발행기에 이벤트 쌓기 -> 나중에 이벤트 처리 -> 재고 줄이기 처리기가 재고를 줄이고 저장

## 그대로인 것
- 앞 장 출력 스물세 줄은 바뀌지 않는다. 첫 주문의 마지막 주문 항목 줄 다음에 주문 뒤 줄과 이벤트 처리 뒤 줄을 더한다
- 상품과 주문 응용 서비스를 만드는 모양은 재고와 발행기만큼 바뀐다. 다른 장면의 출력 글자는 그대로다
- 주문 금액, 할인, 배송비 규칙은 그대로다

## 안 하는 것
- 재고가 모자란 주문 막기: 미룸. 주문과 재고가 따로 맞춰지므로 모자란 것을 나중에 알게 되고, 되돌리는 일은 사가에서 배운다
- 주문 취소 때 재고 되돌리기: 미룸
- 결제 완료 같은 다른 이벤트: 이 장은 주문 접수됨 하나만 만든다
