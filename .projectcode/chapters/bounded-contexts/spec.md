# bounded-contexts 컨텍스트 나누기

종류: 리팩터
배울 것: 하위 도메인, 바운디드 컨텍스트, 모듈, 공유 커널

## 할 일
- S1 업무를 주문(핵심), 상품(지원), 회원(일반) 하위 도메인으로 나누고, 하위 도메인마다 맡는 바운디드 컨텍스트와 묶음 이름을 학생 문서 컨텍스트 맵에 적는다
- S2 돈을 공유 커널 묶음 ddd.shared에 둔다. 컨텍스트들이 함께 쓰는 것은 돈 하나이고, 컨텍스트 맵에 공유 커널로 적는다
- S3 회원, 회원 등급, 회원 저장소, 메모리 회원 저장소를 회원 컨텍스트 묶음 ddd.member 안의 domain, infrastructure에 둔다
- S4 상품, 상품 저장소, 재고 줄이기 처리기, 메모리 상품 저장소를 상품 컨텍스트 묶음 ddd.catalog 안의 domain, application, infrastructure에 둔다
- S5 남은 주문 쪽 클래스를 주문 컨텍스트 묶음 ddd.order 안의 domain, application, infrastructure에 둔다. src/ddd에는 Main과 네 묶음만 남는다
- S6 컨텍스트 안에서도 도메인은 응용과 인프라를 쓰지 않는다. 컨텍스트 사이에 가져다 쓰는 곳(주문이 상품과 회원을 읽고, 상품이 주문 접수됨을 받는다)을 컨텍스트 맵에 적는다

주문 항목: 자바 책 2개, 30000원

주문 뒤: 이벤트 1개, 자바 책 재고 10개
이벤트 처리 뒤: 자바 책 재고 8개
결제: 결제 완료
할인: VIP 3100원, 결제 금액 27900원
배송비: 3000원
배송: 배송 중
취소: 배송 중인 주문은 취소할 수 없습니다
결제 없이 배송: 주문 접수인 주문은 배송할 수 없습니다
음수 금액 주문: 금액은 0원 이상이어야 합니다

가격 바뀐 뒤: 1번 상품 18000원, 주문 항목 15000원, 주문 금액 31000원
동시 수정: 다른 곳에서 먼저 바꾼 주문입니다

## 흐름
업무를 하위 도메인으로 나눔 -> 하위 도메인마다 컨텍스트 -> 공유 커널에 돈 -> 회원, 상품, 주문 컨텍스트 묶음으로 옮김 -> 컨텍스트 사이 쓰는 곳을 컨텍스트 맵에 적음

## 그대로인 것
- 실행 출력 스물여섯 줄은 바뀌지 않는다
- 클래스의 내용은 바뀌지 않는다. 묶음 이름과 가져다 쓰는 줄만 바뀐다
- 컨텍스트마다 안의 계층은 layers 장과 같다. 클래스가 없는 계층 묶음은 만들지 않는다
- 셋을 잇는 일은 지금처럼 ddd 묶음의 Main만 한다
- 용어집은 그대로다

## 안 하는 것
- 컨텍스트마다 돈을 따로 두기: 안 만듦. 돈은 공유 커널로 함께 쓴다
- 자바 모듈로 다른 컨텍스트의 클래스를 못 쓰게 막기: 안 만듦
- 용어집을 컨텍스트마다 나누기: 안 만듦. 용어집은 하나로 두고 컨텍스트 맵에 컨텍스트가 맡는 것을 적는다
- 회원 응용 서비스: 안 만듦. 회원은 저장하고 꺼내기만 한다
- 컨텍스트 사이를 정해진 창구로 잇기: shipping-context 장, payment-acl 장
