# bounded-contexts 컨텍스트 나누기

종류: 리팩터
배울 것: 하위 도메인, 바운디드 컨텍스트, 모듈

## 할 일
- S1 업무를 주문(핵심), 상품(지원), 회원(일반) 하위 도메인으로 나누고, 하위 도메인마다 맡는 바운디드 컨텍스트와 묶음 이름을 학생 문서 컨텍스트 맵에 적는다
- S2 회원, 회원 등급, 회원 저장소, 메모리 회원 저장소를 회원 컨텍스트 묶음 ddd.member 안의 domain, infrastructure에 둔다
- S3 상품, 상품 저장소, 재고 줄이기 처리기, 메모리 상품 저장소를 상품 컨텍스트 묶음 ddd.catalog 안의 domain, application, infrastructure에 둔다
- S4 주문 쪽 클래스는 layers 장부터 주문 컨텍스트 묶음 ddd.order 안의 domain, application, infrastructure에 있다. 회원과 상품을 옮기면 src/ddd에는 Main과 세 묶음만 남는다
- S5 컨텍스트 안에서도 도메인은 응용과 인프라를 쓰지 않는다. 컨텍스트 사이에 가져다 쓰는 곳(주문이 상품과 회원을 읽고, 상품이 주문 접수됨을 받는다)을 컨텍스트 맵에 적는다

## 실행 결과
===== 컨텍스트 나누기 =====

[세 컨텍스트를 거쳐 주문하기]
주문 컨텍스트: 1번 주문, 30000원, 주문 접수
회원 컨텍스트: 김철수, BASIC
상품 컨텍스트: 자바 책 재고 10개 -> 8개

## 흐름
업무를 하위 도메인으로 나눔 -> 하위 도메인마다 컨텍스트 -> 회원, 상품 컨텍스트 묶음으로 옮김 -> 주문은 ddd.order에 그대로 -> 컨텍스트 사이 쓰는 곳을 컨텍스트 맵에 적음

## 그대로인 것
- T1에서 이 장 장면을 찍고, 뒤 task는 출력이 같다. 묶음을 옮겨도 주문, 회원, 상품이 그대로 이어진다
- 클래스의 내용은 바뀌지 않는다. 묶음 이름과 가져다 쓰는 줄만 바뀐다
- 컨텍스트마다 안의 계층은 layers 장과 같다. 클래스가 없는 계층 묶음은 만들지 않는다
- 셋을 잇는 일은 지금처럼 ddd 묶음의 Main만 한다
- 용어집은 그대로다

## 안 하는 것
- 공유 커널: 안 만듦. 금액은 int라 컨텍스트가 함께 지킬 값 객체가 없다
- 자바 모듈로 다른 컨텍스트의 클래스를 못 쓰게 막기: 안 만듦
- 용어집을 컨텍스트마다 나누기: 안 만듦. 용어집은 하나로 두고 컨텍스트 맵에 컨텍스트가 맡는 것을 적는다
- 회원 응용 서비스: 안 만듦. 회원은 저장하고 꺼내기만 한다
- 컨텍스트 사이를 정해진 창구로 잇기: shipping-context 장, payment-acl 장
