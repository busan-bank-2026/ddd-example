# layers 계층 나누기

종류: 리팩터
배울 것: 계층 구조, 의존성 역전

## 할 일
- S1 주문, 주문 항목, 주소, 주문 상태, 주문 저장소를 도메인 계층 묶음 ddd.domain에 둔다
- S2 주문 응용 서비스, 주문 요청, 주문 항목 요청을 응용 계층 묶음 ddd.application에 둔다
- S3 메모리 주문 저장소를 인프라 계층 묶음 ddd.infrastructure에 두고, 도메인 계층의 주문 저장소를 구현한다
- S4 도메인 계층은 응용 계층과 인프라 계층을 쓰지 않고, 응용 계층은 인프라 계층을 쓰지 않는다. 셋을 잇는 일은 ddd 묶음의 Main만 한다

## 실행 결과
온라인 주문 프로그램을 시작합니다
주문: 1번, 김철수, 31000원, 주문 접수
주문 항목: 자바 책 2개, 30000원
주문 항목: 볼펜 1개, 1000원
결제: 결제 완료
배송: 배송 중
취소: 배송 중인 주문은 취소할 수 없습니다
결제 없이 배송: 주문 접수인 주문은 배송할 수 없습니다
음수 금액 주문: 금액은 0원 이상이어야 합니다
빈 주소 주문: 배송 주소를 입력해야 합니다
항목 더하기: 항목 3개, 주문 금액 41000원
결제 뒤 항목 더하기: 주문 접수인 주문에만 항목을 더할 수 있습니다
빈 주문: 주문 항목이 하나 이상 있어야 합니다
0개 항목 주문: 수량은 1개 이상이어야 합니다
두 번 결제: 결제 완료인 주문은 결제할 수 없습니다
배송 완료: 배송 완료
없는 주문 결제: 주문이 없습니다
저장 안 한 취소: 주문 접수

## 흐름
Main -> 응용 계층 주문 응용 서비스 -> 도메인 계층 주문과 주문 저장소 <- 인프라 계층 메모리 주문 저장소가 구현

## 그대로인 것
- 실행 출력 열여덟 줄은 바뀌지 않는다
- 클래스의 내용은 바뀌지 않는다. 묶음 이름과 가져다 쓰는 줄만 바뀐다
- 주문 응용 서비스는 지금처럼 주문 저장소 인터페이스만 받는다. 저장소를 바꾸려면 인프라 계층과 Main만 바꾼다
- 용어집은 그대로다. 계층 이름은 업무 말이 아니다

## 안 하는 것
- 두 번째 저장소 구현 만들기: 안 만듦. 실제 DB 저장소는 하지 않는 것이다
- 묶음 밖에서 못 쓰게 접근 막기: 안 만듦
- 응용 서비스가 주문 대신 조회 결과를 돌려주기: order-query 장
- 컨텍스트로 묶음 나누기: bounded-contexts 장
