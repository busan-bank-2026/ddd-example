# layers 계층 나누기

종류: 리팩터
배울 것: 계층 구조, 의존성 역전

## 할 일
- S1 주문, 주문 항목, 주소, 주문 상태, 주문 저장소를 도메인 계층 묶음 ddd.order.domain에 둔다
- S2 주문 응용 서비스, 주문 요청, 주문 항목 요청을 응용 계층 묶음 ddd.order.application에 둔다
- S3 메모리 주문 저장소를 인프라 계층 묶음 ddd.order.infrastructure에 두고, 도메인 계층의 주문 저장소를 구현한다
- S4 도메인 계층은 응용 계층과 인프라 계층을 쓰지 않고, 응용 계층은 인프라 계층을 쓰지 않는다. 셋을 잇는 일은 ddd 묶음의 Main만 한다

## 실행 결과
===== 계층 나누기 =====

[계층을 거쳐 주문하고 결제하기]
주문: 1번 주문, 31000원, 주문 접수
주문 상태: 주문 접수 -> 결제 완료

## 흐름
Main -> 응용 계층 주문 응용 서비스 -> 도메인 계층 주문과 주문 저장소 <- 인프라 계층 메모리 주문 저장소가 구현

## 그대로인 것
- 세 task 모두 출력은 같다. 계층을 옮겨도 주문하기와 결제하기는 그대로 된다
- 클래스의 내용은 바뀌지 않는다. 묶음 이름과 가져다 쓰는 줄만 바뀐다
- 주문 응용 서비스는 지금처럼 주문 저장소 인터페이스만 받는다. 저장소를 바꾸려면 인프라 계층과 Main만 바꾼다
- 용어집은 그대로다. 계층 이름은 업무 말이 아니다

## 안 하는 것
- 두 번째 저장소 구현 만들기: 안 만듦. 실제 DB 저장소는 하지 않는 것이다
- 묶음 밖에서 못 쓰게 접근 막기: 안 만듦
- 응용 서비스가 주문 대신 조회 결과를 돌려주기: order-query 장
- 컨텍스트로 묶음 나누기: bounded-contexts 장. 계층은 처음부터 주문 묶음 ddd.order 아래에 둔다
